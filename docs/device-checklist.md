# 実機での確認項目

実機（Zenfone 9、AQUOS R10）が使えるようになったら、上から順に確認する。
ここまでの実装は、ビルドと JVM の単体テストまでしか確認していない。

## 準備

1. 端末で開発者向けオプションと USB デバッグをオンにし、Mac につなぐ
2. `adb devices` で端末が見えることを確認する（adb は `/opt/homebrew/share/android-commandlinetools/platform-tools/adb`）
3. `./gradlew :app:installDebug` でインストールする（`JAVA_HOME` は `/usr/libexec/java_home -v 17`）

## 1. カメラの対応状況（最初に見る）

- 設定画面 → 開発用画面で、カメラの高速撮影の対応状況をコピーして保存する
- 背面カメラに `CONSTRAINED_HIGH_SPEED_VIDEO` があるか、使えるサイズと fps を確認する
- 「selected for fpsMode」で、AUTO のときに選ばれる設定を確認する
- 結果を見て、仕様書の「未決事項」（対応端末の下限、フレームレートの扱い）を決める

## 2. 撮影

| # | 確認すること | だめなときに見るところ |
|---|---|---|
| 1 | カメラの権限ダイアログが出て、プレビューが表示され、画面に実際の fps とサイズが出る | 画面上のエラー、logcat のタグ `CaptureController` |
| 2 | 縦持ちでプレビューが正立し、左右反転していない | `GlPipeline.drawFrame` の回転行列 |
| 3 | 240fps／120fps の高速撮影セッションが開ける | 開発用画面の選択結果 |
| 4 | debug 表示の `tb`（エンコーダーと SurfaceTexture の時刻差）が 0 付近 | 数百 ms 以上ずれるなら切り出し範囲の計算を直す |
| 5 | debug 表示の `kf`（キーフレーム間隔）が約 500ms | 0 や 1000 なら端末が丸めている |
| 6 | `gl`、`enc` が目標 fps、`pose` が 15fps 近く、dropped が増え続けない、`buf` が 6〜6.5 秒 | 端末の発熱、カメラの詰まり |
| 7 | ホーム、ロック、一覧への移動でカメラが止まり、戻ると再開する。連打してもクラッシュしない | ライフサイクルとスレッド |

## 3. スイングの検出と保存

| # | 確認すること |
|---|---|
| 1 | スイングすると保存数が増え、一覧に出る |
| 2 | ワッグルや構え直しでは保存されない |
| 3 | 素振りは保存されず、ボールを打ったスイングは保存される（設定でオフにすると素振りも保存される） |
| 4 | 撮影画面を離れると解析が始まり、完了する |

## 4. 解析結果の画面

| # | 確認すること |
|---|---|
| 1 | 動画が縦向きで再生され、骨格の線が体に重なる |
| 2 | コマ送りで 1 コマずつ進む（240fps の動画でも飛ばない） |
| 3 | P ボタンでそのコマに移動する。長押しメニューで P を直せ、自動に戻せる |
| 4 | シークバーの◆をドラッグして P を動かせる |
| 5 | 身長を入れると cm（またはインチ）が出る。メモが保存される |

## 5. 精度の調整（実データが集まってから）

- 自分たちで撮ったスイングに、正解の P1〜P8 のコマを手で付ける
- 自動判定との差（コマ数）を測り、`PhaseDetectorConfig` の閾値を調整する
- `SwingDetectorConfig`、`BallDetectorConfig`、平滑化のパラメータ、cm 換算の係数（0.259）も同様に調整する
- 解析にかかる時間を測る（240fps で 6 秒の動画）
